## 🔒 Git Pre-commit Hooks

In previous modules, we covered **unit testing**, **integration testing**, and **code quality** tools like `isort`, `black`, `pylint`, and `pytest`. Typically, before pushing code, we manually run:

```bash
isort .
black .
pylint --recursive=y .
pytest tests/
```

But what if we forget to run these before every commit? That's where **Git pre-commit hooks** come in — allowing us to **automate code checks before each commit**.

---

### ⚙️ Introduction to Pre-commit Hooks

Git supports **hooks**, which are scripts that run automatically at certain points in the Git workflow. The **pre-commit** hook runs before `git commit` is finalized. These can:
- Prevent bad code from being committed
- Auto-fix issues (e.g., formatting)
- Run tests or linters automatically

We’ll use the [`pre-commit`](https://pre-commit.com/) framework to manage these hooks easily.

If we navigate into the `.git/hooks/` folder of a Git repo:

```bash
ls .git/hooks/
```

We’ll see files like `pre-commit.sample`. These are just **templates**, not active hooks yet.

In our project, we want to test hooks **only on the `code` folder**, which is not a Git repo by default. So, we’ll **initialize it as a separate Git repo** temporarily:

```bash
cd 06-best-practices/code/
git init
```

Now this folder behaves like a standalone repository.

---

### 🧪 Setting Up Pre-commit

1. **Install `pre-commit`**:
   ```bash
   pipenv install --dev pre-commit
   ```

2. **Check its behavior**:
   ```bash
   pre-commit
   
   # Output:
   
   ==> .pre-commit-config.yaml is not a file
   ```

3. **Generate a starter config**:
  ```bash
  pre-commit --help
  pre-commit sample-config
  ls -a # in realty it doesn't show the file
  ```

  Let's generate a config file from sample-config
   ```bash
   pre-commit sample-config > .pre-commit-config.yaml
   ```

5. **View the generated config**:
   ```bash
   cat .pre-commit-config.yaml
   ```

This sample config contains useful default hooks like large file detection, trailing whitespace cleanup, and more. You can now tailor it to your project needs.

5. **Install the Git hooks**:
   ```bash
   pre-commit install
   ```

6. **Confirm the installation**:
   ```bash
   ls .git/hooks/
   ```

You should now see a file named `pre-commit`, generated by the tool. We can check it's content as well:
   ```bash
    less .git/hooks/pre-commit
   ```

Remember: these hooks are **local only** — they won’t be pushed to remote and won’t affect other repos unless explicitly installed.

---
Now if we check the Git status, we’ll see that this is a fresh, standard Git repository.

You can add a `.gitignore` file to exclude files like `__pycache__/`, `.venv/`, etc.

Then, let’s stage and commit everything:

```bash
git add .
git commit -m "initial commit"
```

Before the commit goes through, the configured hooks will run. For example, you may see it clean up trailing whitespaces or flag large files.

You can inspect the changes made by the hooks with:

```bash
git status
git diff
```

Then, commit the new fixes:

```bash
git add .
git commit -m "fixes from pre-commit default hooks"
```

Now everything should pass, and Git logs will reflect both commits:

```bash
git log
```

### ➕ Adding Custom Hooks for Our Workflow

We can configure the pre-commit system to run the following commands automatically before each commit:

```bash
isort .
black .
pylint --recursive=y .
pytest tests/
```

Edit your `.pre-commit-config.yaml` file to include the following hooks:

#### ✅ isort
```yaml
- repo: https://github.com/pycqa/isort
  rev: 5.12.0
  hooks:
    - id: isort
```

#### ✅ black
```yaml
- repo: https://github.com/psf/black
  rev: stable
  hooks:
    - id: black
      language_version: python3.9
```

#### ✅ pylint
```yaml
- repo: local
  hooks:
    - id: pylint
      name: pylint
      entry: pylint
      language: system
      types: [python]
      args:
        [ "-rn", "-sn" ]  # Report messages only, no score
```

#### ✅ pytest
```yaml
- repo: local
  hooks:
    - id: pytest-check
      name: pytest-check
      entry: pytest
      language: system
      pass_filenames: false
      always_run: true
      args: [ "tests/" ]
```

---

### ✅ Using the Hooks

1. Stage your files:
   ```bash
   git add .
   ```

2. Commit:
   ```bash
   git commit -m "Your message"
   ```

The configured tools (`isort`, `black`, `pylint`, `pytest`) will run **automatically** before the commit is accepted.

If there are any issues (e.g., formatting errors), the commit will fail and you'll see detailed output. Fix the issues, stage the changes again, and commit.

---

### 🧹 Cleaning Up or Reinitializing

If you ever want to remove the temporary `.git` setup:

```bash
rm -rf .git
```

Then reinitialize as needed.
